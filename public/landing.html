Features

What it actually does

Two session modes. One passkey. Zero passwords.

Managed sessions

/chat/<project> spawns claude --dangerously-skip-permissions in the project dir. Bidirectional. Stream-JSON parsed, classified, and broadcast to every connected client.

Live mirror

Read-only mirror of any claude you already started — terminal, cmux, or tmux. Tails the JSONL session file. With cmux running, keystrokes are forwarded via Unix socket.

Passkey auth

WebAuthn registration through a one-time bootstrap URL. Single-user owner model. 30-day session cookies. No passwords on disk, ever.

Tunnel-ready

Drop-in with Cloudflare Tunnel or Tailscale Funnel. Set ORIGIN + RP_ID to your public hostname. Same passkey across every device that hits it.

Phone-first UI

iPhone-sized chat by default. iOS-PWA installable. File upload, slash commands, history, agent picker (Claude / Codex / Hermes) — all touch-tuned.

No build step

Vanilla JS frontend. express.static serves from disk. Edit, reload, ship. Cache-busted with query-string versioning. iOS Safari BFCache-safe.

Install

Three commands to a remote Claude Code

  1. 1

    Launch locally

    npx work-on-the-moon
# → http://localhost:3700
# stdout prints a one-time /setup?token=... URL

    Requires macOS, Node.js 20+, and the claude CLI in PATH (autodetected at ~/.local/bin, /usr/local/bin, or /opt/homebrew/bin).

  2. 2

    Register a passkey

    Open the printed setup URL, register Touch ID / Face ID / a hardware key. That device is now the single-user owner.

  3. 3

    Expose via tunnel optional, recommended

    ORIGIN=https://wotm.example.com \
RP_ID=wotm.example.com \
npx work-on-the-moon

    Front with Cloudflare Tunnel or Tailscale Funnel. Same passkey works on phone, laptop, anywhere.

Autostart on macOS

npm install -g work-on-the-moon
wotm install --origin=https://wotm.example.com --rp-id=wotm.example.com
wotm status

Reset state

npx work-on-the-moon reset
# wipes ~/.wotm/data.json
# prints a fresh passkey registration URL
Security model

Built for one trusted owner, not multi-tenant SaaS

What we get right

  • WebAuthn passkeys — no passwords, phishing-resistant
  • HTTP-only cookies, 30-day TTL, atomic disk writes
  • Listens on 127.0.0.1 only — TLS is the tunnel's job
  • Bootstrap registration token is one-shot, 10-minute TTL

What you must accept

  • claude --dangerously-skip-permissions runs file/shell tools without prompting
  • Only expose to your own devices behind TLS
  • No "guest" mode, no multi-user, no read-only sharing
  • If your tunnel is open to the internet without auth in front — don't run this
FAQ

Questions you'd ask before installing

Does this replace the claude CLI?

No. wotm is a launcher and a mirror. The real claude binary still runs locally — wotm just spawns it (Managed mode) or tails its JSONL log (Live mode).

What is "Live mode" actually doing?

It watches ~/.claude/projects/<encoded-cwd>/<session>.jsonl with fs.watch + a 1 s poll, parses new lines, and fans them out to every connected WebSocket client. If the cmux Unix socket is reachable, it also lets you send keystrokes back into the terminal session.

Does it work with cmux, tmux, or screen?

Yes — Live mode mirrors any claude process regardless of which terminal multiplexer launched it, because it reads the JSONL file Claude writes itself. Input forwarding, however, currently requires cmux's Unix socket.

Linux / Windows support?

Planned. The Node.js server is portable; the LaunchAgent installer, node-pty prebuild, and PATH autodetection are the macOS-specific bits.

Will my passkey work across all my devices?

Yes — as long as every device hits the same RP_ID (the public hostname you set with the tunnel). A passkey registered against RP_ID=localhost only works on that machine.

Where is state stored?

~/.wotm/data.json — passkeys, sessions, registration tokens, per-project history. Single file, atomic writes. npx work-on-the-moon reset wipes it.

How is this different from running claude over SSH?

SSH gives you a terminal. wotm gives you a browser UI tuned for phones — slash commands, file upload, agent picker, history, push-to-talk-style send — and a stable URL that survives sleep/wake on either end.
